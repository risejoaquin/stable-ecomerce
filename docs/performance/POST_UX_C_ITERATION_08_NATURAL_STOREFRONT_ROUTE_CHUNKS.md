# POST-UX C - Iteration 08: Restore Natural Storefront Route Chunks

## Evidence

Iteration 07 attributed Lighthouse unused JavaScript exactly.

Product Detail loads:

- shared vendor: ~114.97 KiB transferred, ~59.67 KiB wasted
- storefront-pages: ~28.3-28.55 KiB transferred, ~21.9-22.1 KiB wasted

The `storefront-pages` chunk is therefore about 77.5% unused on Product Detail.

## Root cause

`vite.config.ts` manually assigns every module under:

`/src/pages/store/`

to one `storefront-pages` chunk.

The application already uses lazy routes. This manual grouping defeats part of
that route-level code splitting by merging unrelated storefront page modules
back together.

## Change

Remove only the forced `storefront-pages` manual chunk rule.

Vite/Rollup can then preserve the natural lazy-route boundaries generated by
the application's existing route imports.

## Protected contracts

Unchanged:

- React + ReactDOM + React Router + react-router-dom + lucide-react stay in the
  protected stable `vendor` chunk.
- vendor-query
- vendor-charts
- vendor-commerce
- vendor-observability
- vendor-ui
- admin-pages
- email-admin
- service worker
- auth
- Stripe/checkout

## Expected result

Product Detail should stop paying for unrelated storefront route code. The old
`storefront-pages` chunk should disappear or materially change, and route-
specific page chunks should appear.

## Dependencies

None. Do not run `npm install`.
